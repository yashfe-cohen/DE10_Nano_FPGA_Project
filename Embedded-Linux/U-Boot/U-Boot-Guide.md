## 🔷 טעינה אוטומטית של ה־FPGA בזמן האתחול

אחד היתרונות של U-Boot הוא היכולת לצרוב את ה־FPGA כבר בזמן ה־Boot.

במקום לבצע זאת ידנית בכל פעם, נוסיף מספר פקודות שיגרמו ל־U-Boot לבצע זאת באופן אוטומטי.

תחילה פתחו את סביבת העבודה ב־VS Code.

```bash
code .
```

> 💡 **טיפ עבודה:**  
> במקום לערוך קבצים באמצעות `nano`, הרבה יותר נוח לעבוד ישירות מתוך VS Code.

כעת פתחו את הקובץ:

```
include/config_distro_bootcmd.h
```

לקראת סוף הקובץ תמצאו את ההגדרה:

```c
"distro_bootcmd="
```

יש להחליף אותה בקטע הבא:

```c
BOOT_TARGET_DEVICES(BOOTENV_DEV)                                  \
\
"distro_bootcmd= " \
"if test -e mmc 0:1 u-boot.scr; then " \
"echo --- Found u-boot.scr ---; " \
"fatload mmc 0:1 0x2000000 u-boot.scr; " \
"source 0x2000000; " \
"elif test -e mmc 0:1 soc_system.rbf; then " \
"echo --- Programming FPGA ---; " \
"fatload mmc 0:1 0x2000000 soc_system.rbf; " \
"fpga load 0 0x2000000 0x700000; " \
"else " \
"echo u-boot.scr and soc_system.rbf not found in fat.; " \
"fi; " \
BOOTENV_SET_SCSI_NEED_INIT                      \
BOOTENV_SET_NVME_NEED_INIT                      \
BOOTENV_SET_IDE_NEED_INIT                       \
BOOTENV_SET_VIRTIO_NEED_INIT                    \
"for target in ${boot_targets}; do "           \
"run bootcmd_${target}; "                      \
"done\0"
```

### מה השינוי הזה עושה?

בזמן האתחול U-Boot יפעל לפי הסדר הבא:

1. יבדוק האם קיים הקובץ `u-boot.scr`.
2. אם הקובץ קיים – הוא ייטען לזיכרון ויורץ.
3. אם הקובץ אינו קיים – U-Boot יחפש את הקובץ `soc_system.rbf`.
4. אם נמצא קובץ ה־RBF, הוא יצרוב אותו אל ה־FPGA באופן אוטומטי.
5. לאחר מכן תהליך האתחול ימשיך כרגיל ויטען את מערכת ההפעלה.

גישה זו מאפשרת להפעיל את תכנון ה־FPGA בכל אתחול, ללא צורך בצריבה ידנית מתוך לינוקס.

לאחר שסיימתם לשמור את הקובץ, בצעו Commit:

```bash
git add .

git commit -m "Load FPGA on boot"
```

## 🌐 הגדרת כתובת MAC קבועה

כברירת מחדל, ה־DE10-Nano מקבל כתובת MAC אקראית בכל אתחול.

כתוצאה מכך גם כתובת ה־IP עשויה להשתנות, דבר שמקשה על עבודה באמצעות SSH.

ניצור כתובת MAC קבועה ונוסיף אותה לקוד המקור.

תחילה נייצר כתובת MAC חדשה.

```bash
make -C tools gen_eth_addr
```

לאחר מכן הריצו:

```bash
tools/gen_eth_addr
```

תקבלו כתובת בסגנון:

```text
56:6b:20:e9:4a:47
```

שמרו את הכתובת, מאחר שנשתמש בה בשלב הבא.

כעת פתחו באמצעות VS Code את הקובץ:

```
include/configs/socfpga_common.h
```

חפשו את ההגדרה:

```c
CONFIG_EXTRA_ENV_SETTINGS
```

והוסיפו את השורה:

```c
"ethaddr=56:6b:20:e9:4a:47\0" \
```

כך שהתוצאה תיראה בערך כך:

```c
...
"socfpga_legacy_reset_compat=1\0" \
"ethaddr=56:6b:20:e9:4a:47\0" \
BOOTENV
```

> ⚠️ חשוב מאוד לא למחוק את התו `\0` ואת התו `\` שבסוף השורה, אחרת הקומפילציה תיכשל.

לאחר שמירת הקובץ בצעו Commit נוסף:

```bash
git add .

git commit -m "Added permanent MAC address"
```

# ⚙️ שלב שלישי: הגדרת תצורת U-Boot

לאחר שסיימנו לבצע את ההתאמות הרצויות בקוד המקור, הגיע הזמן להכין את קובץ ההגדרות (Configuration) של U-Boot עבור לוח ה־DE10-Nano.

U-Boot כולל מספר רב של קובצי תצורה מוכנים מראש עבור לוחות שונים. כדי לראות את כל קובצי ההגדרות הזמינים עבור משפחת ה־SoCFPGA, ניתן להריץ:

```bash
ls -l configs/socfpga*
```

במדריך זה נשתמש בקובץ ההגדרות:

```text
socfpga_de10_nano_defconfig
```

צרו את קובץ ההגדרות באמצעות הפקודה:

```bash
make ARCH=arm socfpga_de10_nano_defconfig
```

## פתיחת Menuconfig (אופציונלי)

ברוב המקרים קובץ ההגדרות ברירת המחדל מספיק לחלוטין, ואין צורך לבצע שינויים נוספים.

עם זאת, אם תרצו להוסיף אפשרויות נוספות או לשנות הגדרות קיימות, ניתן לפתוח את ממשק ההגדרות של U-Boot.

```bash
make ARCH=arm menuconfig
```

> 💡 **טיפ:**  
> אם ביצעתם שינויים דרך Menuconfig, אל תשכחו לשמור אותם לפני היציאה.

# 🚀 שלב רביעי: קימפול U-Boot

לאחר שכל ההגדרות מוכנות, ניתן להתחיל בקימפול.

הריצו את הפקודה הבאה:

```bash
make ARCH=arm -j24
```

> ניתן לשנות את הערך של `-j24` בהתאם למספר הליבות במחשב שלכם.

⚠️ **הערה חשובה:**

בדומה לקימפול ה־Kernel, גם כאן **אין להשתמש ב־`sudo make`**.

שימוש ב־`sudo` עלול לשנות את משתני הסביבה ולגרום לשגיאות קימפול, במיוחד כאשר עובדים עם Cross Compiler.

בדרך כלל תהליך הקימפול נמשך מספר דקות, בהתאם לעוצמת המחשב.

# ✅ סיום

אם הקימפול הסתיים ללא שגיאות, יווצר קובץ ה־Bootloader המוכן לצריבה על כרטיס ה־SD.

קובץ הפלט הוא:

```text
u-boot-with-spl.sfp
```

קובץ זה כולל:

- U-Boot
- SPL (Secondary Program Loader)

וזהו הקובץ שבו נשתמש בשלבי ההמשך של בניית מערכת ההפעלה.
